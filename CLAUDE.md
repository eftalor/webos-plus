# LG webOS TV Plus: notes for working on this repo

Custom Home Assistant integration `webos_plus` for LG webOS TVs, built on `aiowebostv`
(the library behind HA's own `webostv`). This file is the developer guide. **The backlog is in
`TODO.md`, the release history in `CHANGELOG.md`.** Personal setup (hosts, deploy commands,
the live HA instance) is in `CLAUDE.local.md`, which is gitignored. Read it if it exists.

To pick up the work, read `TODO.md` ("Next up") and `CLAUDE.local.md`, then ask the user
which item to do.

## Rules

- **This repository is public.** Never commit IPs, MAC addresses, hostnames, entity IDs from
  a real home, tokens, SSH keys or pairing keys. Before each commit run the leak check
  (Release checklist). Personal details go in `CLAUDE.local.md` only.
- Commits use the author's GitHub no-reply email (already set in this repo's local git config).
- Do not send commands to the TV that change what is on screen or its settings without the
  user's OK. Reading state is fine. Test settings changes as "set, then revert".
- The bundled remote card is third-party code (see Layout). Never edit it in place; update it
  only by replacing it with an unmodified upstream release and updating the notices.

## How it works (key facts, verified on a 55UP7550, webOS 6.0)

- **Off is a state, not "unavailable".** While off, a TCP check on port 3000 runs every 5 s
  (every 1 s for 45 s after a turn-on request) and the websocket connects as soon as it opens.
- **Turn on** = Wake-on-LAN to every MAC the TV reported at pairing (wired + Wi-Fi) plus
  `power_on` if still connected (Active Standby). Needs "Turn on via Wi-Fi" on the TV.
- **Pairing**: aiowebostv waits only 10 s; `async_pair` raises `RECEIVE_TIMEOUT` to 60 s.
- **aiowebostv drops subscriptions on every reconnect**, so settings are re-subscribed in
  `_async_update_data` after each connect.
- **SSAP `settings/getSystemSettings`** can read and subscribe: picture backlight, brightness,
  contrast, color, energySaving; sound soundMode. **pictureMode, eyeComfortMode, sleepTimer and
  language are refused.** `com.webos.media/getForegroundAppInfo` 404, `getCurrentSWInformation` 401.
- **Writes without root**: `system.notifications/createAlert` with `onclose` = the luna URI
  (e.g. `luna://com.webos.settingsservice/setSystemSettings`), then `closeAlert`. No result is
  returned; the subscription confirms the change.
- **Root agent** (optional): `tv/agent.sh` installed at `/var/lib/webos-plus/agent`, run as the
  forced command of an ed25519 key generated by the integration (stored in the config entry
  data `agent_private_key`); TV host key pinned on first success (`agent_host_key`). Commands:
  `version`, `stats` (meminfo, CPU from two /proc/stat samples, load, uptime, Netflix RSS, top 5
  processes, picture mode + dynamic range via luna), `free-memory` (closes background apps
  except the foreground app, Home, inputs, Live TV, AirPlay, screensaver, voice). Picture
  modes come from `getSystemSettingDesc` (root only); HDR content uses hdr*/dolbyHdr* modes.
- **TV shell quirks**: `luna-send` prints nothing when stdin is closed (no TTY): use
  `sleep 1 | luna-send -n 1 ...` or `ssh -tt`. BusyBox `timeout -t N`. Dropbear 2022.83.
- **Dashboard strategy**: `window.customStrategies.push({type: "webos-plus", strategyType:
  "dashboard", ...})` + element `ll-strategy-dashboard-webos-plus` with `static async
  generate(config, hass)`. HA 2026.11 lists it under Add dashboard. Entities are found in
  `hass.entities` by `platform === "webos_plus"` and `translation_key` (not by entity_id, which
  users can rename). The card is lazy-loaded only if `lg-remote-control` isn't defined yet.
  The card hard-codes `webostv.*` services, so the strategy passes a `keys:` override for
  every key (buttons -> `webos_plus.button`, media keys -> `webos_plus.command`
  `media.controls/*`). The card's own sound-output popup still calls `webostv` (can't override).
- **HA 2026.11 specifics**: core uses `probatio` (imported as `vol`) instead of voluptuous;
  `typing.override`; `AddConfigEntryEntitiesCallback`; entity services via
  `service.async_register_platform_entity_service`. HACS is the core `marketplace` integration.
  Python 3.14 in the container.
- **HA writes `core.entity_registry` only after startup finishes** (minutes on a Pi), so
  registry checks right after a restart show old values.
- **Code changes need a full HA restart.** Reloading the config entry does not re-import
  Python modules. Frontend files are cached by URL; the strategy URL carries `?v=<version>`.

## Conventions

- Mac Python for local checks: `/opt/homebrew/bin/python3.12` (the system python3 is too old).
  `python3.12 -c "import ast; ast.parse(open(f).read())"` for syntax; the real import check
  runs inside the HA container (see `CLAUDE.local.md`).
- Entities: `_attr_has_entity_name = True`, `translation_key` for every entity (the dashboard
  strategy depends on it). Secondary entities get `EntityCategory.CONFIG`/`DIAGNOSTIC` so the
  auto-generated Overview shows only the media player.
- New strings go into both `strings.json` and `translations/en.json`.

## Release checklist

1. Bump `version` in `manifest.json`.
2. Update `README.md`: the `> Status: early (x.y.z)` line, plus sections for new features.
3. Add an entry to `CHANGELOG.md`; move done items in `TODO.md`.
4. Leak check (must print nothing):
   `git grep -nE '192\.168|10\.77\.|([0-9a-fA-F]{2}:){5}[0-9a-fA-F]{2}|BEGIN OPENSSH|living_room' -- . ':!custom_components/webos_plus/frontend/lg-remote-control.js' ':!CLAUDE.md'`
5. Deploy, restart HA, verify (see `CLAUDE.local.md`), then commit and push.
6. If the bundled card is updated: replace the file with the unmodified release, verify its
   SHA-256 against the GitHub release digest, update version + checksum in
   `THIRD_PARTY_NOTICES.md` and README Credits.
